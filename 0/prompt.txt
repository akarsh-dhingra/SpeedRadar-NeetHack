# Context

## Handle corrupt PDF files in `read_pdf` tool to prevent downstream LLM API errors

**Severity:** High · **Category:** Tool · **Pattern:** Tool contract misuse · **Workflow:** `spendradar` · **Confidence:** 70%
**Status:** Open · **Source:** Auto · **Created:** 2026-10-10 09:47 UTC

## Root cause

The `read_pdf` tool attempts to read PDF files in `mode: "text"` first. When encountering a corrupt PDF file (such as `data/acme/invoices/13_brightloop_2026-10.pdf` which throws `PdfminerException: No /Root object!`), the tool falls back to `mode: "llm"`. However, because the file is fundamentally corrupt and not a valid PDF, passing it to the Gemini LLM (`gemini-3.5-flash-lite` or `gemini-3.1-flash-lite`) results in a non-retryable `400 INVALID_ARGUMENT` error from the Google Generative AI API. This error is not caught gracefully, causing the entire workflow execution to fail.

## Evidence

In trace [View trace](https://app.neatlogs.com/traces/36362eb966cdbb85dcb2fb1b280e1034), the `read_pdf` tool fails with `PdfminerException: No /Root object!` on `13_brightloop_2026-10.pdf`. It then attempts to fall back to `mode: "llm"`, which triggers a `400 INVALID_ARGUMENT` error from `gemini-3.5-flash-lite`. Similarly, in trace [View trace](https://app.neatlogs.com/traces/6fcb0c5ef827b202df85e61406ca16d8), the same fallback triggers a `400 INVALID_ARGUMENT` error from `gemini-3.1-flash-lite`. # Fix

## Recommended action

## Pre-validate PDF files and handle LLM API errors gracefully in `read_pdf` tool

**Steps**

1. Modify the `read_pdf` tool implementation to check if the PDF file is valid before attempting fallback modes.
2. If `pdfplumber` throws a `PdfminerException: No /Root object!` or similar corruption error, do not attempt to fall back to `mode: "llm"`. Instead, immediately return a clear, structured error indicating that the PDF file is corrupt.
3. Add a `try-except` block around the LLM PDF reader call to catch `400 INVALID_ARGUMENT` or other API errors, and return a friendly error message instead of letting the exception bubble up and crash the workflow.

**Verificatio a test script passing a corrupt PDF (e.g., missing `/Root` object) to `read_pdf` and verify it returns a structured error instead of throwing a `400 INVALID_ARGUMENT` exception.
- Run the `spendradar_run` workflow with the test data and verify it completes successfully or handles the corrupt file gracefully.

**Risk assessment**

Low risk. This only changes error handling and validation inside the `read_pdf` tool, preventing unhandled exceptions.

**Rollback plan**

Revert the changes to the `read_pdf` tool implementation in the codebase.
